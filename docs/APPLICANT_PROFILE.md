# 내 신청 조건과 공고 기준 안내

회원가입에서 선택 동의 후 신청 조건을 입력할 수 있다. 기존 회원은 마이 → 설정 → 내 정보 설정 → 내 신청 조건에서 입력·수정·철회한다. 입력하지 않아도 가입과 공고 열람은 가능하다.

## 단계별 회원가입

가입은 닉네임 → 이메일 → 비밀번호·확인 → 내 조건 입력 여부 → 선택한 경우 조건별 질문 → 최종 동의 화면으로 진행한다. 각 조건은 한 화면에 하나씩 표시하고 나중에 입력할 수 있다. 혼인신고일·맞벌이는 혼인 중일 때, 막내 자녀 생년월일은 자녀가 있을 때, 전입일은 지역을 선택했을 때만 묻는다. 앞선 답을 바꿔 질문이 사라지면 관련 값도 제거한다.

닉네임은 가입 흐름을 시작할 때 `임시` + 숫자 6자리로 만든다. 입력창에 처음 포커스하면 임시 값을 비우며, 직접 입력한 이름은 다시 포커스하거나 이전 단계로 돌아가도 유지한다. 비워둔 채 가입하면 처음 표시한 임시 이름을 저장한다. 서버도 빈 이름을 받으면 같은 형식으로 생성하며, 임시 이름의 중복 방지는 보장하지 않는다(이메일이 계정 식별자다).

단계 사이의 입력값은 React 메모리에만 보관한다. 모든 동의를 확인하고 최종 가입 버튼을 눌렀을 때만 서버에 전송한다. 비밀번호를 브라우저 저장소에 저장하지 않는다. 로그인 화면으로 나가거나 페이지를 새로고침하면 작성 중인 입력값은 초기화된다.

## 로그인 후 수정

내 신청 조건은 저장된 값 목록에서 항목 하나를 골라 수정하거나, `하나씩 확인하기`로 질문을 순서대로 확인한다. 가입과 수정은 같은 질문 정의 및 입력 컴포넌트를 사용한다. 저장된 값은 미리 입력되며 `다음`은 기존 답을 보존한다. `이 항목 비우기`만 명시적으로 값을 지운다.

변경값은 메모리의 초안에만 반영하고 `수정됨`으로 표시한다. 목록에서 `변경사항 저장하기`를 눌러야 계정 기록과 맞춤 표시가 바뀐다. 답변 변경으로 더 이상 해당하지 않는 혼인·자녀·거주 관련 값도 지워질 예정임을 안내한다. 저장 실패 시 초안은 유지된다. 가입 직후 프로필 저장이 실패해 넘어온 입력값도 저장된 값과 분리해 다시 저장할 수 있다.

수정 중 닫기, 배경 클릭, Escape, 내 정보 설정으로 돌아가기는 미저장 변경이 있으면 계속 수정하거나 저장 없이 나갈지 확인한다. 저장 요청 중에는 중복 저장과 닫기를 막는다. 조건 삭제·동의 철회는 별도 확인 화면에서 처리한다.

## 입력 항목

| 구분 | 항목 | 사용 목적 |
| --- | --- | --- |
| 기본 | 생년월일, 먼저 볼 신청 대상, 본인·세대원 주택/분양권 보유 여부, 공고 기준 가구원 수, 혼인 상태 | 공고 게시일의 만 나이와 본인 입력 정보를 공식 기준 옆에 표시 |
| 가족 | 혼인신고일, 맞벌이, 미성년 자녀 수, 막내 자녀 생년월일, 세대주 여부 | 신혼·신생아·가구 유형의 관련 원문 기준을 먼저 표시 |
| 소득·자산 | 합산 범위, 세전 월평균 소득, 총자산 가액, 자동차 가액 | 검증된 가구원별 금액표에서 해당 행을 먼저 표시 |
| 거주·청약 | 주민등록 지역, 전입일, 청약 인정 납입 횟수 | 우선순위와 가점 확인 시 입력값 참고 |

추가 항목은 기본적으로 접혀 있다. 미입력과 0을 구분하며 모든 금액은 원 단위다. 가구원 수·소득 합산 범위는 공고마다 달라질 수 있어 사용자가 원문을 확인해야 한다. 주민등록번호, 가족 이름, 임신·장애 상세 정보, 증빙 원본은 수집하지 않는다. 태아·입양·자산 면제 등 예외는 원문에서 확인한다.

## 저장과 계정 분리

- `src/applicantProfile.mjs`에서 허용 필드, 선택 동의 버전, 날짜, 열거값, 숫자를 정규화한다. 서버에서도 같은 검증을 수행한다.
- `jibro_member_notebooks.payload.applicantProfile`에 인증된 계정 ID별로 저장한다. 클라이언트가 소유자를 지정하지 않는다. 기존 revision 기반 충돌 방식을 유지한다.
- 가입 직후 조건 저장에 실패해도 생성된 계정의 로그인은 유지한다. `profileSaved:false` 응답을 통해 입력 내용을 보존하고 다시 저장하도록 안내한다.
- 동의 철회는 `applicantProfile:null`로 저장하며 기존 공고별 확인·서류 기록은 유지한다. 회원 탈퇴는 기존 계정 삭제 절차로 준비 기록과 함께 삭제한다.
- 로그아웃 시 계정 상태가 초기화되고 맞춤 조건 영역은 인증 사용자에게만 표시한다. 브라우저의 공용 로컬 기록으로 계정 프로필을 복사하지 않는다.

## 표시 규칙과 한계

공고 상세와 내 준비의 조건 확인 화면에 동일한 프로필을 전달한다. 선택한 공급 대상의 근거 행과 해당 가구원 수의 소득 행을 우선 표시하며, 일반/맞벌이 금액이 구분된 원문 자료에서는 입력값에 해당하는 금액을 표시한다. 개인 입력값과 공식 기준을 명확히 구분한다.

원문 URL·내용 해시가 해당 공고와 일치하는 기존 발췌/구조화 자료만 사용한다. 다른 공고나 일반 제도 페이지의 금액으로 채우지 않는다. 검증된 금액표가 없거나 5인 이상 행이 없으면 원문 확인 필요로 안내한다. 기존 전체 기준과 원문 링크는 유지한다.

자동 합격/탈락 판정, 신청 자격 확정, 공고 숨김·순위 산정은 하지 않는다. 게시일과 실제 연령 산정일의 차이, 공급대상별 가구원 범위, 출산 가산·면제 등은 사람이 원문과 함께 판단해야 한다.

## 자료 점검과 검증

`node scripts/audit-applicant-fields.mjs`가 현재 저장 목록, 조건 발췌, 구조화 요약, 금액표, 서류 후보 자료를 교차 점검한다. 결과는 `docs/applicant-profile-audit.json`에 기록한다.

2026-09-26 실행 시 대상 공고 90개 중 조건 발췌 90개, 구조화 요약 88개, 검증된 가구원별 금액표 27개, 서류 후보 자료 85개였다. 이 점검은 저장된 발췌와 서류 자료에 대한 검사이며, 모든 PDF를 새로 내려받아 전문을 재심사한 결과가 아니다. 자료가 없는 공고는 보고서에 나열하고 원문 확인 경로를 유지한다.
