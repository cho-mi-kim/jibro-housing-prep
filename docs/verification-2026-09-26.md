# 공고 생애주기·개인별 서류·알림 검증

- 최초 검증 대상: chatgpt.site 소스, 기존 회원 인증·암호화 저장 구조 유지. 이후 GitHub 협업 브랜치에도 소스를 동기화했으며 전달 검증은 `github-sync-2026-09-26.md`에 기록합니다.
- Java 45개, 프론트엔드 73개, 서버 23개, Python 10개 = 총 151개 자동 검사 통과.
- 실제 브라우저: 운영 데이터와 분리된 로컬 계정 미리보기 사용. 320×740에서 가로 넘침 없음. 준비 시작의 로그인 이동, 조건 체크 1/4, 서류 완료 1/5, 새로고침 후 계정 기록/알림 읽음 유지 확인.
- 칠곡왜관4 → 서울 청년 매입임대 공고 전환 시 준비 기록이 섞이지 않음. 대학생 입력 후 서울 공고에 있는 재학·입학·휴학 관련 후보 3개가 '내 조건으로 먼저 확인'에 표시되고 필수 목록에는 자동 추가되지 않음.
- 알림: 칠곡왜관4의 9월 28일 접수 시작·마감 이벤트가 독립 표시. 모두 읽음 후 새로고침해도 읽음 유지. 다른 공고로 전환하면 새 공고의 알림은 별도로 표시.
- 단위 검사: 서로 다른 순위별 기간·잘못된 날짜·자료 없음·당일·기간 종료, 공고/파일 버전 변경, 미버전 과거 기록, 수동 포함/제외 보존, 취소 및 오래된 자료 차단, 공고별 알림 ID와 저장 정규화.
- 수집 서버: 영속 목록 재시작 복원, 수집 실패 시 이전 목록 보존, 주 파일 손상 시 백업 복구, 빈 정상 목록, 저장 실패, 재시도 간격 상한 검사. 스케줄러는 성공 후 기본 6시간 대기하고 실패 시 1·2·4·8·16·32·60분으로 재시도.
- 자료 내보내기: 성공한 공고만 교체, 실패한 공고의 마지막 자료 유지, 실패/복구 상태 별도 기록, 손상된 상태 파일을 임의 덮어쓰지 않음.

## 실행

- 프론트: node scripts/run-frontend-tests.mjs
- 서버: node --test server/account.test.mjs server/notebook-crypto.test.mjs server/mail.test.mjs server/notice-snapshots.test.mjs
- Java: backend/gradlew test bootJar
- Python: python -m unittest discover -s backend/scripts -p 'test_*.py' (backend/scripts/requirements.txt의 의존성 필요)
- 사이트 빌드: node scripts/build-account-site.mjs (자료 카탈로그 자동 생성 포함)

## 검증 한계

이번 변경은 LH 공식 사이트의 전체 자료를 새로 수집한 감사가 아닙니다. 새 공고 전부의 자동 서류 생성, 다른 ID 정정공고 관계, 공개 운영 서버의 정기 실행, 실제 이메일/푸시 발송은 완료로 표시하지 않습니다. 앱의 접수 상태·알림은 저장된 확인 자료 기준이며 이후 공식 정정·조기 마감은 원문 확인이 필요합니다.
