## 실제 동작

- 목록 로딩 → 검색 → 지역·대상 필터 → 공고 상세 → 준비 시작 → 조건·서류·일정 연결.
- 청년 필터 7건에 신혼·신생아 제목이 섞이지 않음. 서울 지역과 청년을 함께 적용하면 2건. 검색 결과 없음은 서버 오류와 별도 안내.
- 칠곡왜관4 공고 A의 연령 확인 → 정관7 공고 B의 상세 열람 후 홈은 A 유지 → B 준비 시작 시 확인 0/4 → B의 무주택 확인 → A로 돌아가면 연령만 체크 → 새로고침 뒤에도 A 기록 보존.
- PDF: 칠곡왜관4의 공식 첨부를 다시 읽어 화면에 `공식 첨부 공고문에서 관련 문구를 발췌했어요`와 실제 확인 시각 표시.
- HWPX: 부산만덕5 2블록 분양전환공공임대주택 공고문을 실제 API로 읽음. 4개 기준의 근거가 반환됐으며 원문 일부 발췌인 `partial` 상태 유지.
- 비공식 URL은 서버가 외부 요청하지 않고 링크만 저장. 화면에도 가짜 날짜·제목·LH 공식 표식이 나오지 않음. 정상 LH 상세 가져오기는 실제 제목과 수집 목록의 정보 연결.
- 서버를 중지하고 새로고침: 90건과 기존 확인 시각 보존, 갱신 실패 문구 표시. 연결 실패 상태에서 새 페이지를 열면 성공한 빈 목록으로 가장하지 않음. 서버 재시작 후 새로고침으로 복구. 수집 중 버튼 비활성화.
- 준비 기록 API의 별도 기기 A/B에 테스트 기록을 저장해 분리 확인. 재시작 후 복원·디스크 저장 실패·깨진 파일은 자동 테스트로 추가 검증.
- 320px·360px에서 목록의 가로 넘침 없음. 새로고침·검색 지우기·분류·지역·관심 버튼을 최소 44px로 보완. 키보드로 검색에 진입할 때 포커스 테두리 표시.
- 별도 로컬 검증 페이지에서 실제 계산된 글자 크기를 200%로 늘리고 320px에서 날짜·지역·필터·하단 메뉴의 잘림을 확인. 확대 시 필터와 메뉴 문구가 줄바꿈됨. 검증 페이지는 제품 소스에 포함하지 않음.

## 남은 운영 범위

- Java API의 운영 배포·정기 작업·영속 저장 경로·운영 CORS 설정은 아직 이 검증으로 완료된 것이 아닙니다. GitHub 브랜치 업데이트와 chatgpt.site 배포는 별개입니다.
- 준비 기록은 기기 헤더 기반이며 사용자 인증·인가가 없습니다. 공개 운영 전 계정·권한 관리와 데이터베이스 전환이 필요합니다.
- 목록 캐시는 서버 메모리에만 있습니다. 서버 재시작 후 수집 실패 시 이전 성공 목록을 디스크에서 복구하지 않습니다.
- 새로운 공고의 서류·일정 스냅샷은 자동으로 만들어지지 않습니다. 이번 작업에서 최신 90건의 모든 첨부·조건·서류를 다시 검토한 것은 아닙니다. 대표 PDF/HWPX의 실제 경로와 기존 파서 회귀 검증을 수행했습니다.
- 제목·지역·유형이 다른 후속 정정공고의 관계는 자동 추정하지 않습니다. LH가 목록 HTML을 바꾸면 수집 실패 안내와 마지막 결과 보존 후 파서 점검이 필요합니다.
- 프론트엔드 빌드에는 기존 단일 번들 크기 경고가 남습니다. 빌드 실패는 아니며 코드 분할은 별도 성능 개선 대상입니다.
