# Spring 회원 서버 전환 검증 · 2026-09-29

범위: React 화면을 유지하고 회원·세션·암호화 준비 기록·메일 처리를 Java 17 Spring MVC로 전환. 실제 chatgpt.site의 계정·키·배포는 변경하지 않음.

## 로컬 확인

- 프론트엔드 테스트 74개 통과, React 배포 빌드 성공. 기존 큰 JS 청크 경고는 남음.
- Java 전체 테스트 59개 통과 및 실행 JAR 생성 성공. H2의 PostgreSQL 호환 모드 사용.
- Python 자료 분석 도구 테스트 10개 통과. 로그인과 Python은 연결하지 않음.
- 실제 `preview:account` 명령으로 Spring 8080 + React 5173 기동, 포트 중복 시 기존 서버를 건드리지 않도록 검사.
- 브라우저에서 admin 로그인 → 공고 준비 시작 → 조건 체크 → 새로고침 → Spring 종료·재실행 후 같은 공고와 1/4 체크 복원 확인.
- 320px에서 가상 회원의 단계별 가입·로그인·마이 설정 확인. 새 계정에 admin의 기록이 나타나지 않음. 테스트용 실제 개인정보·발송 서비스는 사용하지 않음.
- 메일 미설정 상태에서 화면은 발송 준비 중·미인증으로 표시. 실제 이메일 전달은 미검증.
- 이전 Worker로 생성한 합성 비밀번호 해시·암호문을 Spring에서 읽고 로그인 후 해시 갱신. 계정 ID·동의·가구 정보·근거 버전·알림 읽음·revision 유지.
- 별도 파일 DB에서 오프라인 이관 명령의 검증 → 적용 → 재적용 확인. 최초 1명 적용, 재적용 0명/기존 1명 건너뜀.
- 합성 SQLite 백업 내보내기에서 해시·암호문 일치, 기존 출력 파일 덮어쓰기 거부 확인.

## 보안·정합성 자동 검증

동의·비밀번호·신청 조건 검증, 누락 CSRF·잘못된 Origin·콘텐츠 형식·초과 본문 차단, 계정 간 분리, 로그아웃/비밀번호 변경/탈퇴 후 세션 차단, 세션·메일 토큰 만료/재사용 거부, 요청 제한, 두 창 동시 저장 시 1건 성공/1건 409, 키 교체·다른 회원 암호문/변조 거부, 이관 키 누락·이메일 충돌·재실행 시 덮어쓰기 방지.

## CI와 남은 확인

GitHub CI에 PostgreSQL 16 서비스에서 같은 회원 통합 테스트를 실행하도록 추가했습니다. CI 실행 결과는 PR에서 별도로 확인합니다. 로컬에서는 PostgreSQL 서버가 없어 H2 검증만 수행했습니다.

운영 서버 배포, 기존 실제 회원 이관, Resend 실제 전달, 운영 프록시·TLS·백업·다중 기기 검증은 아직 하지 않았습니다. 수집기 동작 변경이 아니므로 실제 LH 재수집은 이번 검증에서 반복하지 않았습니다. 기존 수집 검증 기록을 유지합니다. 미완료 작업은 [TODO](TODO.md)에 정리했습니다.
